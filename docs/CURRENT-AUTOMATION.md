## K80 迁移细节与已知问题

- 系统 Android 16，现有钱包 com.mipay.wallet、拼多多 com.xunmeng.pinduoduo、私人浏览器 app.penrix.browser。K80 没有 su，现有 Shizuku 以 Shell UID 运行。
- AutoJs6 APK 的官方 SHA-256 为 a4fa5c941aecc4dbb770316e35ac98ae5b0efef5041ac0533dfa826b94595525。本地校验一致的包为旧下载缓存 autojs6-ghfast.apk。另一个名为 autojs6-v6.7.0-arm64.apk 的缓存哈希不同，未用于本次安装。
- 已通过真实权限检查。k80-probe.json 返回 accessibility=true、shizuku=true、code=0。现有其他无障碍服务按原列表保留。
- K80 源码将 Root shell 调用改为 Shizuku。钱包桌面 VideoWidget 实例 ID 由 K20 的 4 改为 K80 实际查到的 44；这只证明小部件实例存在，不证明第三次领取成功。
- K80 电源模块最终使用 device.wakeUpIfNeeded / keepScreenOn(240000)，遇到安全锁屏会停止并提示解锁。仅对最终模块做过语法检查，熄屏定时、锁屏、跨日、重启后的运行未验证。旧系统 screen_off_timeout 从临时 180000 恢复为原 600000。
- AutoJs6 已加入电池优化白名单并允许精确闹钟。通过 ADB 直接启动 AppForegroundService 被系统拒绝为非导出服务，K80 前台服务保活尚未完成实机验证。不能将 K20 的 Root 守护复制为 K80 已可用结论。
- Epic 原先调用内部 BrowserActivity，被 K80 系统以 not exported 拒绝。K80 候选脚本改为启动 MainActivity，再通过真实地址栏进入 Epic。真实 Free Games 页面已出现。
- Epic 随后遇到前台切换及页面读取等待。中途有旧引擎停止/重新启动重叠，出现带 finished_at 但 status=started 的结果，不算成功。最新候选源码已部署，最后一次 audit 启动后本窗口被中断，没有最终结果可用。
- Epic 候选登录函数当前会提示在 K80 浏览器登录，尚未验证自动登录；策略仍依赖旧 WebView 的英文目录描述及中文商品/结账标签，需按 K80 真实树修正。先完成这条链路，再声明可每日自动入库。
- PDD 日/周成功限制在脚本中保留。设备成功账本按本机维护；若两台手机使用同一个账户，合并的日/周上限尚未验收。
