# 02｜Node-01：K20 Pro 固定基线

## 设备身份

当前第一台自动化节点：

```text
Node-01
Redmi K20 Pro
Codename: raphael
6 GB RAM
128 GB Storage
Snapdragon 855
ARM64
MIUI 10 9.6.3 开发版
Android 9
Root
无电池
电容 + 外部供电
24×7 长期在线用途
```

它不是用户的主力手机。

主要职责是：

- 游戏挂机；
- 拼多多抢券；
- 自动签到 / 收菜；
- 后续 Android 自动化任务。

---

## 为什么旧系统不急着升级

对普通用户来说，新 Android 版本通常更安全、更现代。

但这个节点的目标不同。

这里的价值是：

- 环境固定；
- Root 已经可用；
- Android 9 对很多旧自动化工具更友好；
- 后台限制比新系统少；
- 分辨率、DPI、ROM 行为更容易固定；
- 一些 Alas 安卓本机化历史方案本来就是旧 Android / Snapdragon 855 一代环境。

因此当前默认原则：

> **没有明确收益，不为了“更新”而更新 ROM。**

如果未来某个关键执行器明确要求更高 Android，再单独评估。

---

## 为什么“固定设备”是自动化优势

对于普通软件，硬编码设备环境通常是坏事。

但私人单机自动化不一样。

我们只有明确目标：

> 让 Node-01 稳定完成固定任务。

所以可以主动利用确定性：

- 固定分辨率；
- 固定 DPI；
- 固定导航方式；
- 固定字体缩放；
- 固定 ROM；
- 固定 Root 环境；
- 尽量固定 App 版本；
- 固定横竖屏方向。

这会极大降低视觉自动化和坐标适配成本。

---

## 6 GB RAM 的使用原则

不要为了“节点化”同时常驻很多重负载程序。

建议：

```text
同一时刻：
1 个主要游戏
+
1 个轻量 Supervisor/runtime
+
必要系统服务
```

其他任务：

```text
需要时启动
→ 做完
→ 退出 / force-stop
```

不要常态同时跑：

- 多个大型游戏；
- 重 OCR；
- OpenCV 大模型；
- 多套 Python runtime；
- 多个调试服务；
- 不必要模拟环境。

---

## 无电池意味着什么

无电池 + 电容意味着：

优点：

- 非常适合固定供电长期挂机；
- 避免电池长期充电膨胀问题。

代价：

> **掉电没有缓冲。**

因此项目必须假设：

```text
任何时刻都可能突然断电
```

所以：

- 状态写入要小而可靠；
- 不要长时间只把关键状态留在内存；
- 任务结果要及时落盘；
- 启动后要能从持久状态恢复；
- 后续可考虑稳定电源 / UPS，但不作为软件首期前置。

---

## 开机恢复的长期目标

最终希望做到：

```text
来电
→ 手机开机
→ 网络恢复
→ 自动化 runtime 启动
→ Supervisor 启动
→ 读取上次状态
→ 恢复调度
```

但“断电后来电自动开机”属于设备 / bootloader / ROM 级问题。

目前不假定已经解决。

---

## 开发连接

开发期可通过 Windows：

```text
ADB
scrcpy
必要时 uiautomator2
必要时 Airtest / OpenCV
```

但这些不能成为运行期硬依赖。

---

## 已知设计优势

Node-01 特别适合当前项目的原因：

1. Snapdragon 855 性能足够；
2. ARM64；
3. Android 9；
4. 已 Root；
5. 无个人数据负担；
6. 固定供电；
7. 可牺牲用户体验换稳定自动化；
8. 可长期固定 ROM / DPI / App 环境；
9. 可以把它当设备而不是消费手机维护。

---

## 后续需要实测而不是猜的项目

以下不要仅凭文档推断：

- 实际屏幕分辨率；
- DPI；
- 导航模式；
- AutoJs6 当前版本兼容性；
- Accessibility 节点质量；
- RootAutomator / shell input / Accessibility click 实际延迟；
- MFABD2 Android APK 在 MIUI 10 上的权限行为；
- Alas 本机化所需 Linux/Python 依赖；
- 息屏 / 前台 / 后台运行稳定性；
- 系统是否会杀自动化进程。

这些应通过真实 Node-01 验收后再写成 VERIFIED。
